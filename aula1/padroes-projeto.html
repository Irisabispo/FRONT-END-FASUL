Padrões de Projeto Front-end

Padrões de projeto são soluções comprovadas e amplamente utilizadas para problemas recorrentes no desenvolvimento de software. Eles fornecem diretrizes e abordagens para a criação de arquiteturas de software mais eficientes, modularizadas e flexíveis.

Introdução

A aplicação de padrões de projeto adequados é fundamental para garantir a qualidade e a manutenibilidade do código, além de facilitar a evolução do sistema ao longo do tempo. Os padrões de projeto fornecem diretrizes e soluções comprovadas para problemas recorrentes no desenvolvimento de software.

MVC - Model-View-Controller

Um dos padrões de projeto mais comumente aplicados no front-end é o Model-View-Controller (MVC), que separa a lógica de negócio, a apresentação e a interação do usuário em três componentes distintos. Essa separação permite uma melhor organização do código e facilita a manutenção, uma vez que as responsabilidades estão claramente definidas.

Model

Representa os dados e a lógica de negócio

View

Responsável pela apresentação visual da interface

Controller

Controla as interações entre o Model e o View

Benefícios: A adoção do padrão MVC ajuda a separar as responsabilidades e torna o código mais modular e flexível, o que facilita a manutenção do sistema, uma vez que alterações em um componente não afetam diretamente os outros.

Singleton

O padrão Singleton garante que apenas uma instância de uma determinada classe seja criada, permitindo o acesso global a essa instância. Esse padrão é útil em situações em que é necessário compartilhar dados ou recursos entre diferentes partes do sistema.

Exemplo de Singleton:

class Configuracao {
    constructor() {
        if (Configuracao.instance) {
            return Configuracao.instance;
        }
        this.configuracoes = {};
        Configuracao.instance = this;
    }

    set(key, value) {
        this.configuracoes[key] = value;
    }

    get(key) {
        return this.configuracoes[key];
    }
}

// Uso
const config1 = new Configuracao();
config1.set("tema", "escuro");

const config2 = new Configuracao();
console.log(config2.get("tema")); // "escuro" - mesma instância

console.log(config1 === config2); // true

Observer

O padrão Observer estabelece uma relação de dependência entre objetos, na qual um objeto, conhecido como Subject, mantém uma lista de outros objetos, conhecidos como Observers, e os notifica automaticamente sobre quaisquer mudanças de estado. Essa abordagem permite que os Observers reajam de acordo com as alterações do Subject.

Exemplo de Observer:

// Subject (Observable)
class EventManager {
    constructor() {
        this.listeners = {};
    }

    on(event, callback) {
        if (!this.listeners[event]) {
            this.listeners[event] = [];
        }
        this.listeners[event].push(callback);
    }

    emit(event, data) {
        if (this.listeners[event]) {
            this.listeners[event].forEach(callback => callback(data));
        }
    }
}

// Uso
const eventos = new EventManager();

// Observer 1
eventos.on("usuario-login", (dados) => {
    console.log("Usuário logado:", dados.nome);
});

// Observer 2
eventos.on("usuario-login", (dados) => {
    console.log("Enviando email para:", dados.email);
});

// Disparar evento
eventos.emit("usuario-login", {
    nome: "João",
    email: "joao@email.com"
});

Factory Method

O padrão Factory Method define uma interface para criar objetos, mas permite que as subclasses decidam qual classe concreta instanciar. Isso permite a criação de objetos de forma flexível e desacoplada, facilitando a manutenção e a evolução do sistema.

Exemplo de Factory Method:

// Interface Product
class Product {
    getPrice() {
        throw new Error("Método getPrice() deve ser implementado");
    }
}

// Produtos concretos
class Clothing extends Product {
    getPrice() {
        return 50;
    }
}

class Electronic extends Product {
    getPrice() {
        return 500;
    }
}

class Book extends Product {
    getPrice() {
        return 30;
    }
}

// Factory
class ProductFactory {
    createProduct(type) {
        switch (type) {
            case "clothing":
                return new Clothing();
            case "electronic":
                return new Electronic();
            case "book":
                return new Book();
            default:
                throw new Error("Tipo de produto inválido");
        }
    }
}

// Uso
const factory = new ProductFactory();
const camisa = factory.createProduct("clothing");
console.log(camisa.getPrice()); // 50

Strategy

O padrão Strategy permite encapsular diferentes algoritmos em classes separadas, permitindo a seleção dinâmica de um algoritmo específico em tempo de execução. Isso torna o sistema mais flexível e fácil de manter.

Exemplo de Strategy:

// Estratégias de ordenação
class SortStrategy {
    sort(data) {
        throw new Error("Método sort() deve ser implementado");
    }
}

class BubbleSort extends SortStrategy {
    sort(data) {
        console.log("Ordenando com Bubble Sort");
        return [...data].sort((a, b) => a - b);
    }
}

class QuickSort extends SortStrategy {
    sort(data) {
        console.log("Ordenando com Quick Sort");
        return [...data].sort((a, b) => a - b);
    }
}

class MergeSort extends SortStrategy {
    sort(data) {
        console.log("Ordenando com Merge Sort");
        return [...data].sort((a, b) => a - b);
    }
}

// Contexto
class TaskSorter {
    constructor(strategy) {
        this.strategy = strategy;
    }

    setStrategy(strategy) {
        this.strategy = strategy;
    }

    sortTasks(tasks) {
        return this.strategy.sort(tasks);
    }
}

// Uso
const tasks = [5, 2, 8, 1, 9];
const sorter = new TaskSorter(new BubbleSort());
console.log(sorter.sortTasks(tasks)); // [1, 2, 5, 8, 9]

sorter.setStrategy(new QuickSort());
console.log(sorter.sortTasks(tasks)); // [1, 2, 5, 8, 9]

Dependency Injection

O padrão Dependency Injection permite injetar dependências em um objeto em vez de criá-las diretamente dentro dele. Isso torna o sistema mais flexível, pois as dependências podem ser facilmente substituídas ou modificadas sem impactar o código do objeto.

Exemplo de Dependency Injection:

// Serviço de usuário
class UserService {
    constructor(repository) {
        this.repository = repository;
    }

    getUser(id) {
        return this.repository.findById(id);
    }
}

// Repositórios
class MongoRepository {
    findById(id) {
        return { id, name: "João", source: "MongoDB" };
    }
}

class PostgresRepository {
    findById(id) {
        return { id, name: "João", source: "PostgreSQL" };
    }
}

// Uso com injeção de dependência
const mongoRepo = new MongoRepository();
const userServiceMongo = new UserService(mongoRepo);
console.log(userServiceMongo.getUser(1));

const postgresRepo = new PostgresRepository();
const userServicePostgres = new UserService(postgresRepo);
console.log(userServicePostgres.getUser(1));

Module

O padrão Module consiste em dividir o código em módulos independentes, cada um responsável por uma funcionalidade específica do aplicativo. Esses módulos podem ser desenvolvidos separadamente e depois integrados ao aplicativo, facilitando a manutenção e a evolução do sistema.

Exemplo de Module:

// Módulo de carrinho de compras
const ShoppingCart = (() => {
    let items = [];

    return {
        addItem(item) {
            items.push(item);
            console.log(`${item} adicionado ao carrinho`);
        },
        removeItem(item) {
            const index = items.indexOf(item);
            if (index > -1) {
                items.splice(index, 1);
                console.log(`${item} removido do carrinho`);
            }
        },
        getItems() {
            return [...items];
        },
        getTotal() {
            return items.length;
        }
    };
})();

// Módulo de produtos
const ProductModule = (() => {
    let products = [];

    return {
        addProduct(product) {
            products.push(product);
        },
        getProducts() {
            return [...products];
        },
        getProductById(id) {
            return products.find(p => p.id === id);
        }
    };
})();

// Uso
ShoppingCart.addItem("Camisa");
ShoppingCart.addItem("Calça");
console.log(ShoppingCart.getItems()); // ["Camisa", "Calça"]

MVVM - Model-View-ViewModel

O padrão Model-View-ViewModel (MVVM) permite a ligação entre a camada de visualização (View) e a camada de modelo de dados (Model) por meio de um objeto intermediário (ViewModel). O ViewModel atua como uma ponte entre a View e o Model, fornecendo os dados e comportamentos necessários para a interface de usuário.

Características: O ViewModel também pode conter lógica adicional para manipulação dos dados e eventos relacionados à interface. Essa separação clara entre as responsabilidades facilita o desenvolvimento, a manutenção e o teste do código front-end.

MVP - Model-View-Presenter

O padrão Model-View-Presenter (MVP) separa a lógica de apresentação da lógica de negócio por meio de um componente intermediário chamado Presenter. A View é responsável pela exibição dos dados ao usuário, o Model é responsável pela lógica de negócio e o Presenter atua como uma ponte entre a View e o Model, controlando a interação e o fluxo de dados.

Benefícios: Essa separação permite uma melhor organização e testabilidade do código, além de facilitar a manutenção e a evolução do sistema, pois as responsabilidades são claramente definidas e distribuídas entre os componentes. O MVP é amplamente utilizado em aplicações web e desktop que demandam uma separação clara entre a interface do usuário e a lógica de negócio.

Os padrões de projeto oferecem soluções comprovadas para problemas recorrentes no desenvolvimento de software e promovem a criação de arquiteturas mais modulares e flexíveis. Com a aplicação desses padrões, é possível criar sistemas front-end mais robustos, fáceis de manter e prontos para se adaptarem a novas exigências e necessidades do mercado.
